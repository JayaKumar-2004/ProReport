CHAPTER 1: INTRODUCTION

1.1 Introduction to Raksha-Suraksha

Raksha-Suraksha is the implementation of a military-grade personal safety and anti-theft application using Android (Java) and Python backend servers. The rapid development of wireless technologies over the last decade has added great convenience to our lives, but it has also increased the risk of digital and physical theft.

To accommodate different security requirements, Raksha-Suraksha acts as an offline-first command center. It leverages existing SMS traffic to achieve communication even when internet connections are disabled by thieves. It utilizes hash maps and local SQLite databases for accessing data securely.

1.2 Problem Definition

In this project we will be creating a simple but highly effective application which helps to protect devices without the need for active internet. This will be very useful to secure personal data, track stolen devices offline, and emit SOS signals during emergencies.

1.3 Objectives

Raksha-Suraksha is designed to help users secure their mobile devices autonomously. The app typically has an interface that allows users to manage secure passwords, track locations via SMS, and trigger loud alarms even if the device is in DND mode.

1.4 Scope

The project aims to develop a robust and efficient security system capable of running in the background without draining battery. This involves implementing algorithms for parsing SMS commands, mapping GPS coordinates, and handling special cases such as crash detection via gravity sensors.

2.1 Literature Review

A literature survey for a mobile security application involves delving into existing research, articles, and resources related to Android architecture, background services, and native API programming. This comprehensive review serves as the foundation for understanding the domain.

Firstly, the survey explores the historical significance of mobile tracking, tracing its origins to standard GPS modules. Next, the survey delves into various representations of offline databases, including SQLite implementations. By analyzing different encoding schemes, the project can ensure compatibility and flexibility.

2.2 Existing System

Advanced users frequently employing security tools rely on dedicated software applications. Existing applications offer a wider range of functionalities but heavily rely on active internet connections to function, which is their primary point of failure.

2.3 Proposed System

The proposed system aims to develop a robust and user-friendly offline tracking converter using Android Native APIs. Raksha-Suraksha remains relevant in various environments, offering a seamless defense process, error handling, and a graphical user interface (GUI) for enhanced usability.

CHAPTER 4: IMPLEMENTATION

4.1 Implementation Strategy

Android provides data structures and shared preferences which store information in the form of key-value pairs, which is very convenient for implementing secure vaults. We can save the user's emergency contacts in a local SQLite dictionary.

4.2 Methodology

In the case of an emergency, we extract the exact GPS coordinates and match them with the user's trusted contacts stored in the data structure. We store the payload in a variable which will contain our SMS string. We repeat this process until we traverse the entire emergency list.

4.3 Module Description

We have mainly two modules which are the Background Ghost Tracker and the User Interface Dashboard.

CHAPTER 6: SOFTWARE TESTING

There are many different testing levels which help to check behavior and performance for software testing. These testing levels are designed to recognize missing areas and reconciliation between the development lifecycle states.

6.1 Unit Testing

A unit testing is a smallest testable portion of system or application which can be compiled, located, and executed. This kind of testing helps to test each module separately. This kind of testing is performed by developers.

6.2 Integration Testing

Integration means combining. Different software modules are combined and tested as a group to make sure that the integrated system is ready for system testing. Integrating testing checks the data flow from one module to other modules.

6.3 System Testing

System testing is performed on a complete, integrated system. It allows checking system compliance as per the requirements. It involves load, performance, reliability and security testing.

6.4 Acceptance Testing

Acceptance testing is a test conducted to find if the requirements of a specification or contract are met. Acceptance testing is basically done by the user or customers.

6.5 Types of Testing: Black Box & White Box

Black Box Testing is defined as a testing technique in which functionality is tested without looking at the internal code structure. White-box testing is a method that tests internal structures or workings of an application.
